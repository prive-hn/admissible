# Premise — fail-closed work projection

Roque Briceño. 27 August 2026. Companion to `INVARIANTS.md` and `LEMMAS.md` in this directory.

This is a **Ready addendum**, not an eighteenth identity theorem. Layer I does not grow. The process is **fail-closed work projection**. Live object: **work package**. Finished object: **authenticated projection**. It claims no new mathematics: domain separation and snapshot isolation are old. It states the missing process lemmas for stochastic agents and for the build that reviews them.

## 0. What the base does not answer

Layer I answers: did the worker we bound actually run. Layer R answers: was the artifact attacked hard enough before a seal. Layer C answers: what has been found against it since.

A connected agent makes cheap, plausible patches. None of I, R, or C answers: **was this check the check this agent was permitted to run on this exact tree?**

A review generation makes cheap, plausible verdicts. None of I, R, or C answers: **does this verdict still name the candidate that now sits on the branch?**

If one blob is used as task, permit, and artifact, a check without a package, or a package that authorizes a different HEAD, is constructible. If one verdict is used across a moving head, tree, or patch digest, approval hops. Both are the same failure shape as Red Admissible’s K0: one digest asked to be comparison, authorization, and wire at once.

## 1. What this addendum is not

Not a quality theorem. Not a claim that the agent’s patch is good. Not I18. Not a citation-bound, mutation-killed result until the three digests are typed, domain-tagged, and the guards exist as named methods. Until then these are lemmas to implement, not theorems to cite.

Presentation surfaces (local status query, stdio agent surface) write no admission field. Passing checks is not Ready. A later byte change is a different candidate.

## 2. Method

The lemmas cite I3, I9, I10, I17, R11, and Red F0–F5. They compose by non-interference: the projection machine writes no field of I, R, or C. The build-identity lemma is I7 and I17 applied to candidates, not to work items.

## 2a. What the v0.8.0 runtime separation adds, and what it does not

The product this addendum describes now installs as separate distributions: `admissible-ready`, which may start a candidate's commands and ships no credential loader, and `admissible-trust`, which holds the review, observer and admission keys and ships no runner, no agent surface and no server. Neither depends on the other; neither wheel contains the other's modules.

That is a **process separation contract**, and it is carried here because P0's guard obligation is stated in terms of which capabilities may sit in one process. It is **not a proof**. It removes accidental capability adjacency and it is not an operating-system sandbox: anything already running under the same account can read the environment, edit the store and delete the files, and package boundaries do not survive that. No lemma is promoted by it. P0–P3 remain unproved.

**Red Admissible is unchanged** by this separation, and **no new composition claim** is made about it here. Red consumes a separately verified projection only in a later, separately scoped change; nothing in the split licenses composing this family with Red's, and the K0 analogy in §0 above remains an analogy.

Positions held before writing, so they can fall:

- That Ready v0.7 already proved projection because inspect is fail-closed in code. **Code is not a theorem.** Unguarded library entry, optional package identifiers, and mid-check HEAD change remain constructible.
- That review-generation fences are operations, not process. **A fence that transfers APPROVE across a new tree is an unbound hop.** The churn of a large agent build is the same hole, one layer up.
